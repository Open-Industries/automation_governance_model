== Selección de mecanismo
[cols="1,1,1",options="header"]
|===
|Mecanismo
|Uso
|Custodia y límite
|AAP Credential
|Conexión a destino o SCM
|RBAC, rotación y acceso Execute según objeto
|Credential Type personalizado
|Proveedor específico
|Inyectores de variables o archivos mínimos, revisados
|HashiCorp Vault
|Centralizar rotación y acceso temporal
|Auth por workload, path limitado y auditoría
|Ansible Vault
|Archivo cifrado versionado
|Password fuera de Git, rotación y acceso al texto descifrado
|===


No confundir HashiCorp Vault y Ansible Vault. Cifrar un archivo no elimina la necesidad de gestionar contraseña y acceso. HashiCorp Vault puede integrarse como fuente externa de credential según la versión de AAP. Revisar soporte y plugin exactos.

== Flujo de credencial
. Seguridad define acciones, destino, TTL y rotación.
. El custodio crea credencial y autoriza al equipo correspondiente.
. AAP Admin asocia la credencial al template y evita prompts que permitan elegir otra.
. Dev usa variables inyectadas o lookup aprobado. Añade `no_log: true` sólo a las tareas que procesan valores secretos.
. Operaciones revisa que logs, diffs y artifacts estén saneados antes de notificar.
. El custodio rota, valida nueva credencial y revoca la anterior.

`no_log` reduce exposición en tareas, pero no garantiza que un secret no aparezca en otra variable, debug, excepción o output. `diff: false` evita mostrar contenido sensible de archivos. No registrar `hostvars` completos.

== Ejemplo de Ansible Vault
[source,bash]
----
ansible-vault create inventories/lab/group_vars/all/vault.yml
ansible-playbook -i inventories/lab/hosts.yml playbooks/virtualizacion.yml --ask-vault-pass
----
El laboratorio no necesita secrets. Este comando sirve para practicar custodia con datos sintéticos y no debe introducir credenciales reales al workshop. En AAP usar el tipo Vault correspondiente para la contraseña.

== Incidente por secret en Git
Revocar y rotar inmediatamente, identificar consumidores y alcance, notificar al custodio y remediar exposición. Borrar el texto del último commit no lo elimina del historial. Una reescritura de historial requiere coordinación con SCM y participantes.
